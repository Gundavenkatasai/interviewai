# Day 19 Test Environment Strategy

## Infrastructure Isolation
The Day 19 E2E and Load Testing will execute against an isolated test environment to prevent production data corruption.

- **Backend**: Runs on `localhost:3000` (Node.js/Fastify) via `npm run dev` or built `dist`.
- **Frontend**: Runs on `localhost:5173` (Vite) pointing strictly to the local backend.
- **Database (MongoDB)**: `mongodb://localhost:27017/applyhustle_e2e_test`
- **AI Provider**: `FakeAIProvider` (used for load testing limits and isolating DB/Application performance). Tests that validate timeout and hallucination boundaries will use the staging AI credentials.

## Environment Variables
Test execution requires the following specific environment injection (e.g., via `.env.e2e`):

```env
NODE_ENV=test
PORT=3000
MONGODB_URI=mongodb://localhost:27017
MONGODB_DB_NAME=applyhustle_e2e_test
JWT_SECRET=e2e_isolated_secret_key_999
FRONTEND_URL=http://localhost:5173
```

## Dataset & Seeding
A deterministic seeder script (`tests/seed/e2e-seed.ts`) generates realistic entities required for the golden path.
All synthetic data generated by this script will include a strict prefix or marker (`[TEST_ONLY]`) where applicable.

- **Candidates**: 5 deterministic test users.
- **Resumes**: 5 variations of canonical resumes.
- **Jobs**: 50 varied jobs (remote/onsite, high/low match, Greenhouse/Lever).
- **Interviews**: 10 completed mock interviews with consistent weaknesses.
- **Applications**: 31 submitted applications distributed across the funnel for Analytics integrity tests.

## Cleanup Strategy
- The E2E seeder uses `mongoose.connection.dropDatabase()` prior to each test run to ensure strict cleanup and isolation.
- Test identities are bound uniquely to the session to avoid cross-test state leakage.
